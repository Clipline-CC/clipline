# Stable 1.0.2

> **For agentic workers:** Execute this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for
> tracking and remain unticked by repository convention.

**Goal:** Promote develop to `main` and publish GitHub Stable **1.0.2** — the same content as
Nightly 1.0.2 with the Stable update-channel default baked in.

**Why 1.0.2 and not 1.0.1:** One version triple feeds both channels. Stable never invents a
number; it takes develop's. develop sits at 1.0.2 (published as Nightly 1.0.2), so the Stable is
1.0.2. A 1.0.1 Stable would require downgrading the version files, ship Nightly 1.0.2's code
under a lower number, and strand nightly-1.0.2 installs that switch to Stable ("no update").
Nightly ≥ Stable is the standing invariant; equality is benign — identical content on both
channels, and per-channel manifests mean neither channel's updater loops.

**Release-worthy user-visible changes since Stable 1.0.0:** everything in Nightly 1.0.1 and
1.0.2 — the update-dialog/flow fixes (#169, #170), install-package default update channel
(#172), changelog link in the update dialog (#171), hidden cloud actions while signed out
(#173), the NSIS uninstaller with replay-ownership and credential-scope hardening (#174), and
recording sidecars leaving storage quota totals plus delete-all-managed-media.
