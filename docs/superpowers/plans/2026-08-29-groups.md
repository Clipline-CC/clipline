# Groups TDD Plan

**Goal:** Let a user export the current trim into a named ordered group, open that group from the
Library, reorder its clips, export the group as one compilation, and send that compilation through
the existing Clipline Cloud upload flow.

**Architecture:** Extend each clip's existing `.clipline.json` metadata with an optional
`group { name, order }` value. The Library derives groups from clip metadata, so a group is created
by its first clip and disappears when its last clip is deleted. No database or separate group file
is needed. Group compilation is one bounded FFmpeg job that normalizes every member to 1080p60
H.264/AAC, concatenates in stored order, and writes a normal local `compilation` clip. Upload reuses
the current upload dialog and `upload_clip_to_cloud` command.

## Task 1: Metadata and membership

- [ ] Add failing library tests for metadata round-tripping, group name validation, first/next
      order assignment, and moving a member up/down.
- [ ] Add optional group membership to `ClipMetadata`, `ClipInfo`, and `ExportedClipInfo` without
      changing legacy sidecar behavior.
- [ ] Extend `export_clip` with an optional group name and assign the canonical existing group name
      plus the next order when present.
- [ ] Add a path-validated `move_group_clip` command that swaps one member with its neighbor.

## Task 2: Compilation export

- [ ] Add failing tests for ordered-member selection, missing/one-member groups, bounded group size,
      safe FFmpeg argument construction, and compilation naming.
- [ ] Add `export_group` in `library/groups.rs`: derive members from authoritative metadata,
      normalize mixed dimensions/audio presence, encode one H.264/AAC MP4, and publish a normal
      `compilation` clip plus metadata.
- [ ] Reuse the existing bounded FFmpeg runner, console suppression, encoder probing, path
      validation, asset scoping, and storage refresh paths.

## Task 3: Add-to-group UI

- [ ] Add a failing UI contract for the secondary `Add to group` action and accessible chooser.
- [ ] Put `Add to group` beside the existing Clip action. The dialog lists existing groups and a
      `New group` choice; confirmation exports the current trim with the chosen membership.
- [ ] Insert the returned grouped clip into the local cache and refresh storage using the existing
      export flow.

## Task 4: Library group view

- [ ] Add a failing UI contract for group cards, ordered rows, move controls, export, and upload.
- [ ] Render a Groups section in the local Library. Clicking a card opens a dialog with ordered
      members, Up/Down controls, and clip-open actions.
- [ ] Export creates the compilation and refreshes the Library. Upload creates the same compilation
      and opens the existing title/description/visibility dialog for it.
- [ ] Keep groups local-only; Cloud continues to show uploaded compilation videos as ordinary clips.

## Task 5: Verification and handoff

- [ ] Run focused app tests, `cargo test --workspace`, and
      `cargo clippy --workspace --all-targets -- -D warnings`.
- [ ] Update `ddoc.md` and `handoff.md`.
- [ ] Stop an existing Clipline process, launch `cargo run -p clipline-app`, and hand off the exact
      add/reorder/export/upload scenarios for manual testing.

## Deliberate v1 limits

- A compilation contains at most 64 clips because the direct FFmpeg input list must fit the Windows
  process command line. Move to staged concat inputs only if real groups hit that ceiling.
- Group rename, duplicate/copy, and moving an already-existing clip into a group are deferred; the
  requested creation path starts from the review trim action.
