# Nightly 0.1.42 Release

> **For agentic workers:** Execute this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for
> tracking and remain unticked by repository convention.

**Goal:** Publish the merged memory-footprint and review-audio work as the signed-updater Nightly
0.1.42 release: PR #109 (clip-start audio repeat), PR #106 (replay retention, hidden-webview memory,
split meter), and PR #107 (memory follow-ups, native software H.264 MFT, FFmpeg thumbnail hardening).

**Release-worthy user-visible changes since 0.1.41:**

- The split-second audio repeat at the start of every clip is gone (#109).
- Replay memory tracks the footage a save can use rather than the byte budget's overshoot headroom —
  measured 85.8 MB → ~45 MB retained at the dev machine's settings, recording process 147–180 MB →
  ~103 MB (#106).
- Hiding to the tray now releases WebView2 rendering resources instead of keeping them resident:
  tray-idle process tree ~335 MB → ~155 MB. Cold autostart no longer renders indefinitely (#106).
- The RAM meter reports Clipline's own process separately from child processes, so webview cost is no
  longer blended into the app figure (#106).
- Large-library rendering is bounded, thumbnails self-recover, taskbar lifecycle recovers without
  focus, and active clip sources are protected during upload (#107).
